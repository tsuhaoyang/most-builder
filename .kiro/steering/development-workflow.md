# DDM v2 Development Guidelines

## Daily Workflow

### Starting Development
1. **Environment Setup**: Use virtual environment with Python 3.11
2. **Dependencies**: Install from lock files: `pip install --require-hashes -r requirements-dev.lock`
3. **Database**: Run migrations and seed data before starting work
4. **Frontend**: `npm install` and verify build passes before changes

### Making Changes
- **Branch Strategy**: Feature branches from main, descriptive names
- **Atomic Commits**: One logical change per commit, clear commit messages
- **Test First**: Write or update tests before implementing features
- **Documentation**: Update relevant docs when changing behavior

### Before Committing
1. **Tests**: `PYTHONPATH=src pytest` (unit + integration if DB available)
2. **Linting**: `ruff check` and `ruff format` for Python
3. **Type Check**: `mypy` for Python, `npm run typecheck` for TypeScript
4. **Build**: `npm run build` for frontend changes
5. **Core Logic**: Run golden test validation if touching MOST engine

## Common Tasks

### Adding New API Endpoint
1. Define Pydantic schema in `src/ddm_v2/schemas/v2/`
2. Implement route in appropriate `src/ddm_v2/api/routes/v2/` module
3. Add service layer logic with proper error handling
4. Include authentication/authorization checks
5. Write integration tests with realistic data
6. Update OpenAPI documentation if needed

### Database Changes
1. Create migration: `PYTHONPATH=src alembic revision --autogenerate -m "description"`
2. Review autogenerated SQL carefully, edit if needed
3. Test upgrade and downgrade paths
4. Update model classes if needed
5. Add seed data migration if required

### Frontend Feature Development
1. Create feature module in `src/frontend/src/features/<feature>/`
2. Implement API client with proper TypeScript types
3. Build React components with proper error boundaries
4. Add loading and error states for all async operations
5. Write Playwright E2E tests for critical user paths
6. Ensure responsive design and accessibility compliance

## Problem Solving

### Database Issues
- **Connection Errors**: Check DATABASE_URL format and PostgreSQL status
- **Migration Conflicts**: Use `alembic merge` for branch conflicts
- **Performance**: Use `EXPLAIN ANALYZE` to diagnose slow queries
- **Data Corruption**: Always test with backups, never edit production directly

### API Problems  
- **Authentication Failures**: Verify RBAC configuration and user roles
- **Validation Errors**: Check Pydantic schema definitions match API usage
- **Performance Issues**: Profile with async tools, check N+1 queries
- **CORS Issues**: Verify origin configuration in development vs production

### Frontend Issues
- **Build Failures**: Check TypeScript errors and dependency compatibility
- **Runtime Errors**: Use React error boundaries and proper error handling
- **State Management**: Debug with React DevTools and TanStack Query DevTools
- **E2E Test Flaking**: Ensure proper waits and stable selectors

### MOST Engine Issues
- **TMU Calculation Errors**: Verify against golden test vectors first
- **Rule-set Problems**: Check version compatibility and data integrity
- **Level Validation**: Compare against R1-R9 specification documents
- **Performance**: Profile calculation engine with realistic datasets

## Code Review Checklist

### Security & Safety
- [ ] No hardcoded secrets or credentials
- [ ] Proper input validation and sanitization
- [ ] RBAC checks in place for protected resources
- [ ] SQL injection prevention (parameterized queries)
- [ ] Error messages don't leak sensitive information

### Functionality
- [ ] Business logic matches requirements and specifications
- [ ] Edge cases handled appropriately
- [ ] Error paths tested and documented
- [ ] MOST calculations match golden vectors if applicable
- [ ] Level System rules properly enforced

### Code Quality
- [ ] Clear, self-documenting code with appropriate comments
- [ ] Consistent with existing project patterns
- [ ] Proper error handling and logging
- [ ] Performance considerations addressed
- [ ] Tests provide adequate coverage
