# DDM v2 Project Conventions

## Code Organization

### Python Backend
- **Python Version**: 3.11+ (aligned with CI and Dockerfile)
- **Package Structure**: All code under `src/ddm_v2/` for proper namespace
- **API Routes**: Use `/api/v2` prefix for all endpoints
- **Async Patterns**: SQLAlchemy 2.0 async throughout, no sync DB operations
- **Import Style**: Absolute imports from `ddm_v2.*`, use `PYTHONPATH=src` for scripts

### Frontend
- **Framework**: React 19 + TypeScript strict mode
- **Architecture**: Feature-based modules in `src/frontend/src/features/<tab>/`
- **Shared Code**: Common components in `src/frontend/src/shared/`
- **State Management**: TanStack Query for server state, Zustand for client state
- **Styling**: TailwindCSS utility-first approach

### Dependencies
- **Lock Files**: Always install from `.lock` files to match CI/Docker exactly
- **Security**: Pin exact versions, run pip-audit for vulnerability scanning
- **Backend**: Use `requirements-dev.lock` for dev dependencies
- **Frontend**: Use `package-lock.json` for reproducible builds

## Development Workflow

### Database
- **Migrations**: Always use Alembic, never manual schema changes
- **Seed Data**: Development seeds in `scripts/`, idempotent design
- **Version Control**: Include migrations in commits, review autogenerated files
- **Testing**: Use `DATABASE_URL` for integration tests, skip if not available

### API Design
- **Authentication**: Use `require_role()` with proper RBAC levels
- **Validation**: Pydantic v2 schemas for all request/response data
- **Error Handling**: Structured error responses via `error_handlers.py`
- **OpenAPI**: Maintain API documentation automatically

### Testing Strategy
- **Unit Tests**: Mark with `@pytest.mark.unit`, no external dependencies
- **Integration Tests**: Mark with `@pytest.mark.integration`, require DB
- **E2E Tests**: Playwright for frontend, test against full stack
- **Core Logic**: Golden test vectors must always pass (regression prevention)

## Quality Standards

### Code Style
- **Python**: Ruff for linting/formatting (configured in pyproject.toml)
- **TypeScript**: Strict mode enabled, no `any` types
- **Line Length**: 120 characters for both Python and TypeScript
- **Comments**: Focus on WHY not WHAT, especially for business logic

### Security
- **Input Validation**: Always validate at API boundaries
- **SQL Injection**: Use parameterized queries, never string concatenation
- **Authentication**: Never bypass RBAC checks in development
- **Dependencies**: Keep security patches current, monitor CVEs

### Performance
- **Database**: Use appropriate indexes, review query plans
- **API**: Async patterns throughout, proper connection pooling
- **Frontend**: Code splitting, lazy loading for large features
- **Bundle Size**: Monitor and optimize build outputs

## MOST Domain Knowledge

### Core Concepts
- **TMU Units**: 1 TMU = 0.036 seconds, basis for all time calculations
- **GM/CM Format**: 7-position sequences (A/B/G/P/M/X/I values)
- **Level System**: R1-R9 rules, main/sub/cub/nb relationships
- **Rule-sets**: Versioned data (not code), supports rollback and audit

### Business Rules
- **Single Authority**: Backend engine is the only calculation source
- **Version Snapshots**: All worksheets capture rule-set version used
- **RBAC Levels**: viewer < IE < manager < admin (respect throughout UI)
- **Audit Trail**: Track who changed what and when for compliance
