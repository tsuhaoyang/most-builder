# <票 ID> 需求條目　← 複製後改成實際票號

> 本檔是 REQ 模板。複製整檔到票目錄（`<票庫>/<ID>/requirements.md`）後，
> 把檔頭 frontmatter 的 `類別` 改成 `REQ`、`狀態` 改成 `Draft`，填下列各節。
> 類別宣告見 `rules/doc-taxonomy.md` §1.0；REQ 的時態／可否引為依據／最小必填見 §1.8。
> **模板本身宣告 `TEMPLATE → REQ`，不得被引為實作依據。**

複製後的檔頭 frontmatter 形狀（示範；`---` 為上下閉界）：

```yaml
---
類別: REQ
狀態: <Draft → 已定案 → 已取代；§1.8／§1.9>
票: <prefix>-NN
凍結於: DESIGN 定案（rules/doc-taxonomy.md §1.8）
偏離: <一句話指路——無 REQ 模板時怎麼寫、形狀照哪個先例；沒有就寫「無」>
---
```

<一句話來源：這批 REQ 從哪裡抽出來（ticket.md 的現況／影響／要做／範圍、state.yaml 的 open_questions）。>

## REQ-<n>　<一句話標題>

- **statement：** <這條需求要什麼。寫「要做到什麼」，不寫「怎麼做」——怎麼做屬 design。>
- **驗收意圖：** <不能壞：<哪些既有語意／規則不得因本條改變>。失敗：<什麼情況算這條沒做到>。>
- **priority：** <must ｜ should　← 正式詞彙二選一>

<每條 REQ 一節，標題固定、anchor 用標題。ID 形狀 `REQ-<n>`，票內唯一，全域定址 `<票號>/REQ-<n>`。>
