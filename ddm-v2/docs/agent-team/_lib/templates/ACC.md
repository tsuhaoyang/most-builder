## 4. 驗收項

每條驗收項先標**型別**，型別決定哪些欄位必填：

| 型別 | 意思 | 額外必填 |
|---|---|---|
| `NEW` | 新行為必須成立 | — |
| `REGRESSION` | 既有行為**不得改變** | **基線證據**（須在 `implement` 開始前取得） |
| `NEGATIVE` | 某件事必須**做不到** | **對照組**（同一測試在修正前必須失敗） |

## 5. 修訂紀錄

ACC 定案後凍結。修訂＝**開新版**，舊版保留原文並標 `superseded_by`，**human 重新核可**。

正當理由只有三類：`DESIGN 變更` / `門檻不可達` / `驗證方式無效`。

> **「結果不如預期」不是正當理由。**
> 改 ACC 讓它通過，是整套流程裡最便宜、也最毀滅性的一個動作——
> 它讓驗收失去意義，而且不會報錯。

| 版本 | 日期 | 理由（三類之一） | 核可 | 受影響項 |
|---|---|---|---|---|
| v1 | | 初版 | | — |
